$ Go REST APIs on Cloudflare Workers

A beginner-friendly walkthrough that leans on the Go standard library and adds exactly one dependency.

# The one thing to understand first

Cloudflare Workers do not run native binaries. Each Worker executes inside a V8 isolate — the same engine that runs JavaScript in Chrome — which can run JavaScript and WebAssembly (WASM). So "Go on a Worker" really means:

main.gostandard net/http
→
compileGo → WASM
→
app.wasm+ tiny JS shim
→
Cloudflare edge300+ cities

The glue is one package: github.com/syumai/workers. It catches the Worker's fetch event and feeds it to a plain Go http.Handler. Everything else you write is ordinary standard-library Go.

Why this is great for beginners If you can write a net/http server on your laptop, you can write a Worker. The deployment target changes; the Go you write barely does.

# No web framework required

As of Go 1.22, the standard-library router (http.ServeMux) understands HTTP methods and path wildcards. A full REST API with typed routes needs zero third-party packages:

routing — pure stdlib
mux.HandleFunc("GET /books/{id}", getBook)
id := r.PathValue("id") // reads {id} — built in since Go 1.22

# Scaffold the project

The maintainers ship official templates. This one command creates the folder, the Go module, the JS shim, and a working wrangler.toml:

terminal
npm create cloudflare@latest -- \
  --template github.com/syumai/workers/_templates/cloudflare/worker-go

cd my-app
go mod tidy

For the free-tier build, use the TinyGo template instead: .../worker-tinygo.

# Run it locally

terminal
npm start                       # wraps `wrangler dev`
curl http://localhost:8787/hello

Wrangler runs the real Workers runtime locally (via workerd), so what you see on localhost is what runs at the edge.

$ Write the API

Replace the template's main.go with this. It's standard library top to bottom, except the final bridge call.

# 1. Model & in-memory store

main.go
type Book struct {
    ID     int    `json:"id"`
    Title  string `json:"title"`
    Author string `json:"author"`
}

// In-memory + per-isolate + ephemeral. Fine for a demo;
// use Workers KV / D1 for real persistence (see Going Further).
var db = newStore()
The struct tags do the JSON `json:"title"` tells encoding/json how to name fields. No serialization library needed.

# 2. A handler — read a path param

main.go — GET /books/{id}
func getBook(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.Atoi(r.PathValue("id"))   // {id} wildcard
    if err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "id must be a number"})
        return
    }
    b, ok := db.books[id]
    if !ok {
        writeJSON(w, http.StatusNotFound, map[string]string{"error": "book not found"})
        return
    }
    writeJSON(w, http.StatusOK, b)
}

# 3. Wire routes & hand off to the Worker

main.go — func main()
func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /books",        listBooks)
    mux.HandleFunc("GET /books/{id}",   getBook)
    mux.HandleFunc("POST /books",       createBook)
    mux.HandleFunc("DELETE /books/{id}", deleteBook)

    // The ONLY non-stdlib line. Registers a fetch listener and
    // blocks forever — never let main() return.
    workers.Serve(mux)
}
Gotcha workers.Serve must not return. If main() exits, your Worker exits. Don't put cleanup code after it.

The complete file is in worker/main.go in this folder — including listBooks, createBook, deleteBook, and the writeJSON helper.

$ Deploy to the edge

From localhost to a global URL in three steps.

  1. Authenticate Wrangler with Cloudflare

    terminal
    npx wrangler login   # opens a browser, one time
    A free Cloudflare account is all you need.

  2. Build the WASM and deploy

    terminal
    npx wrangler deploy
    Wrangler runs the [build] command from wrangler.toml (generate JS glue → go build to WASM), then uploads it. You'll get a live URL:
    output
    https://books-worker.<your-subdomain>.workers.dev

  3. Hit your live API

    terminal
    curl https://books-worker.<you>.workers.dev/books
    It's now served from the Cloudflare edge — requests hit the nearest of 300+ cities automatically.

# What's in wrangler.toml

wrangler.toml
name = "books-worker"
main = "./build/worker.mjs"        # JS shim that boots the WASM
compatibility_date = "2025-01-01"

[build]
command = "go run github.com/syumai/workers/cmd/workers-assets-gen -mode=go \
  && GOOS=js GOARCH=wasm go build -o ./build/app.wasm ."
Free-tier build Swap the second build line for tinygo build -o ./build/app.wasm -target wasm . (and -mode=tinygo) to produce a sub-1 MB binary that fits the free plan.

CPU time ≠ wall-clock time You're billed for CPU, not total duration. Waiting on a database or upstream API is free — only the milliseconds your code actively computes count. A typical JSON handler uses a few ms.

# Guard against surprise bills

Set a hard CPU ceiling per request in wrangler.toml so a runaway loop can't run up charges:

wrangler.toml
[limits]
cpu_ms = 50   # request is killed past this

# Real persistence

Module globals (our map) live per-isolate and vanish. For durable data, bind a storage product — all have generous free tiers:

ProductUse it for
Workers KVsimple key/value, read-heavy, eventually consistent
D1SQLite at the edge — real SQL, relational data
Durable Objectsstrongly-consistent state, coordination, websockets
R2object/blob storage, S3-compatible, no egress fees

The syumai/workers package exposes Go bindings (e.g. a cloudflare/kv sub-package) so you read these from Go.

# The stdlib-vs-TinyGo decision

 Regular GoTinyGo
Standard libraryfullpartial
Binary size3–8 MB< 1 MB
Fits free planusually noyes
Reflection-heavy libsyeslimited

Recommended path: develop with regular Go (everything works), then switch the build to TinyGo for free-tier deploys. For a plain JSON API — encoding/json, net/http routing, strconv — TinyGo handles it fine.

# Production checklist

  • Add CORS headers if a browser frontend calls the API.
  • Validate & bound request bodies — never trust input.
  • Return consistent JSON error shapes (the demo's writeJSON helps).
  • Add a GET /healthz route for uptime monitoring (included in the demo).
  • Set [limits] cpu_ms to cap cost.
  • Use wrangler tail to stream live logs from production.
