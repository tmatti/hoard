# GitHub License Options — Pros & Cons

An interactive report comparing the pros and cons of every software license in
GitHub's "Choose a license" picker (the set curated by
[choosealicense.com](https://choosealicense.com)).

## What's here
- **index.html** — tabbed dark-mode dashboard (open in any browser):
  - **Overview** — the 13 options and the adoption-vs-protection trade-off
  - **Families** — the permissive → copyleft → network-copyleft spectrum diagram
  - **Matrix** — all 13 licenses across patent grants, copyleft scope, attribution,
    source disclosure, and GPL compatibility
  - **Pros & Cons** — per-license cards, filterable by family
  - **Decision Guide** — a pick-a-license flow
- **notes.md** — working notes, the source list, and the key gotchas.

## Licenses covered
Permissive: **MIT, Apache-2.0, BSD-3, BSD-2, Boost (BSL-1.0)** ·
Copyleft: **MPL-2.0, EPL-2.0, LGPL-3.0, GPL-3.0, GPL-2.0, AGPL-3.0** ·
Public domain: **Unlicense, CC0-1.0**

## TL;DR
- Widest adoption, least text → **MIT**
- Permissive + patent protection → **Apache-2.0**
- Improvements come back, proprietary code still allowed → **MPL-2.0**
- Whole derivative stays open → **GPL-3.0**
- Even SaaS users get the source → **AGPL-3.0**
- No strings at all → **Unlicense / CC0**

> ⚠ Educational summary, not legal advice. Verify against choosealicense.com and SPDX.
